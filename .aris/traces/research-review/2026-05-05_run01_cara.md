## Round 1: Pairwise Streaming GRPO — Initial Proposal

**Our claim**: Replace K-way GRPO with streaming pairwise contrastive updates; train on first (pos, neg) pair per prompt.

**Reviewer verdict**:
- Novelty: 4/10 (not 9/10 as initially assessed)
- Impact: 6/10
- Overall: "explore, but do not pitch the current claim set"

**Critical issues found**:
1. Unbiasedness claim is FALSE — conditioning on discordant pairs introduces prompt-dependent reweighting bias
2. Main novelty threat is P3O (2310.00212), not AReaL — P3O already does online pairwise PG
3. GRPO K=2 already is essentially pairwise for binary rewards — discordant pairs give opposite advantages
4. Pair scarcity problem: expected draws to first contrast = 1/(p(1-p)) - 1, blows up at p→0 or p→1

## Round 3: AIRS Method — Deterministic Stopping Rule

**Our proposal**: AIRS = stop when n_pos>=1 AND n_neg>=1, or discard if K_max reached with no contrast.

**Reviewer verdict**:
- Mostly captured by AERO (2602.14338): AERO already does adaptive allocation, early exit, Bayesian posterior
- AIRS is a weaker special case of AERO unless adding: event-driven streaming, or principled stop rule AERO doesn't have
- Variable-K GRPO normalization issue: stopping at first pair biases toward balanced micro-groups
- Strongest objection: "AIRS removes the strongest parts of AERO — why should it outperform?"

**Strongest remaining novelty**: adaptive rollout stopping as sequential budget-allocation problem (not just stop-on-first-pair)

---

## Round 4: CARA — Final Method

**Final method**: CARA (Cost-Aware Adaptive Rollout Acquisition)
- Cost-aware marginal-utility stopping: continue only while expected_gain / expected_cost >= threshold
- Two thresholds: τ_rescue (for all-same prompts) and τ_balance (for mixed prompts seeking curate_per_sign pairs)
- Balanced curation: random per-sign subsampling to curate_per_sign positives + curate_per_sign negatives
- Prompt-equalized loss: mean over sequences within prompt, then mean over prompts

**Method formalized**:
```
p_pos = (β_α + n_pos) / (β_α + β_β + n_total)  [Beta posterior]
cost_hat = max(min_cost_tokens, mean_new_tokens)

rescue mode (all-same): continue if 1000 * p_gain / cost_hat >= τ_rescue
balance mode (mixed):   continue if 1000 * p_gain / cost_hat >= τ_balance
                        where p_gain = P(minority sign)
stop when: curate_per_sign pairs per sign collected, or K_max reached
```

**Key differentiation from AERO**:
- AERO: stratified, posterior-guided, mixed-prompt-aware (complex)
- CARA: cost-aware unified stopping rule + balanced curation (simpler, cost-explicit)
- CARA positions as "maximize informative gradient per rollout token" Pareto frontier

**Novelty assessment after full discussion**:
- AIRS-hard: heuristic baseline (acceptable, not novel)
- CARA: "adaptive rollout stopping as sequential budget-allocation" — the cost-aware aspect + balanced curation make it distinct from AERO

**Reviewer recommended name**: CARA (Cost-Aware Adaptive Rollout Acquisition for Grouped RLVR)

## Experiment Plan (Concrete, from Reviewer)

### Pilot (2h, 1 GPU)
- Generate K_max=8 completions for 512 prompts offline
- Replay 5 schedulers: GRPO-K8, GRPO-K4, AIRS-hard, CARA (3 threshold settings)
- Gate: >=25% lower tokens than K8, >=90% mixed-prompt recall, beats K4 at similar token cost

### Full run (~1 day, 4×A100)
1. 2h implementation + smoke test
2. 2-3h rollout-only microbench (1024 prompts)
3. 12-16h end-to-end training: GRPO-K8, GRPO-K4, CARA-full + 4 ablations

### Ablation table
Main: GRPO-K8, GRPO-K4, AIRS-hard, CARA-full
Ablation: CARA-no-cost, CARA-no-equalize, CARA-curate1, CARA-curate2
Optional: AERO-lite

### Publishable result threshold
- CARA reaches 0.9× final K8 accuracy with >=20% fewer rollout tokens and >=15% less wall-clock
- Final accuracy within 0.5pp GSM8K, 1.0pp MATH vs K8
- CARA beats K4 on final accuracy at similar rollout-token cost
